# ADR 0006 — P2.1 Built-in CRM: design decisions

- **Status:** Accepted
- **Date:** 2026-07-16
- **Context:** PRD v1.4 §6.12 (Built-in Education CRM), §14 addendum, `docs/BUILD-PLAYBOOK.md` P2.1

## Context

P2.1 builds the native CRM on top of the existing lead-capture foundation (the
`leads` table, public `POST /api/v1/leads`, `AuditLogger`). §6.12 and the
playbook leave several points ambiguous or in tension; this ADR records the
calls made so the build is unambiguous and later phases know the seams.

## Decisions

1. **Lead scoring is rule-based, behind an interface.** §6.12 describes an "AI
   score from engagement telemetry"; the playbook scopes P2.1 to a "rule-based
   stub". We ship `App\Services\Crm\LeadScorer` (interface) +
   `RuleBasedLeadScorer` (points for high-intent type, reachable email, live
   course, paid UTM). P3 rebinds the interface to the telemetry model — no
   caller changes.

2. **Meta Lead Ads webhook uses Meta's native scheme.** `GET /webhooks/meta/leads`
   is the subscription handshake (echoes `hub.challenge` when `hub.verify_token`
   matches `services.meta.verify_token`); `POST` deliveries are HMAC-verified by
   `meta.signed` middleware (`X-Hub-Signature-256` = `sha256=` +
   HMAC-SHA256(rawBody, `META_APP_SECRET`)), mirroring the Zoom verifier.
   Unsigned/invalid → 403. Tests mock the signature the same way
   `ZoomWebhookTest` does.
   - **Tenant resolution** for the webhook is by `META_TENANT_SLUG` (single Meta
     business per deployment for P2.1), falling back to the domain default slug.
     Per-page → tenant mapping is deferred.
   - **Inline `field_data`** is mapped straight to a lead. Payloads carrying only
     a `leadgen_id` (requiring a Graph API fetch) are acknowledged and skipped —
     that fetch is a later enhancement, not P2.1.

3. **`lead_stages` is its own per-tenant table**, seeded with the §6.12 funnel
   (Lead → Masterclass Registered → Attended → Bootcamp → Reserved/Payment
   Pending → Enrolled → Active → Placement-Ready → Placed). P2.1 owns manual
   stage moves. **Payment/enrolment-driven transitions** (Reserved→Enrolled on
   instalment 1 — playbook P2.2) are a deliberate seam: `LeadStageChanged` is
   emitted so P2.2 can drive them; the batch-membership↔stage sync is not built
   here.

4. **Phone dedupe key = normalized digits, per tenant.** `phone_normalized`
   (non-digits stripped) is stored and indexed `[tenant_id, phone_normalized]`.
   The merge tool defaults the **oldest lead as survivor** (stable id + original
   UTM attribution), folds blank fields + both timelines + tasks into it,
   tombstones the loser (`merged_into_id`), and audits `crm.lead_merged`. The
   counselor may override which record survives.

5. **A counselor is a staff user holding `manage-leads`** — no new entity. The
   `counselor` and `admin` roles already grant it (`RolePermissionSeeder`).
   Assignment is `leads.assigned_to → users.id`. Round-robin state is a pointer
   on the per-tenant `crm_assignment_rules` row.

6. **Speed-to-lead SLA default is 15 minutes** (tenant-configurable via
   `crm_assignment_rules.sla_minutes`). `CheckLeadSla` is dispatched delayed to
   `sla_due_at`; on firing, if the lead is still untouched and past due it flags
   the breach, drops an SLA task on the assignee, and records a timeline event.
   The job self-guards against the sync driver ignoring the delay (no breach
   before due) and is idempotent.

7. **Follow-up sequences ("auto-pause on reply") are deferred to P2.4.** They
   depend on two-way messaging (inbound-reply detection). First touch is marked
   when a counselor logs a note; the task queue + SLA tasks ship now.

## Consequences

- The AI scorer, Meta Graph-fetch, per-page tenant mapping, payment→stage sync,
  and follow-up sequences are explicit, owner-visible deferrals — not gaps.
- SQLite (test DB) cannot add FK constraints via `ALTER TABLE`, so the new
  columns on `leads` carry indexes only; the fresh CRM tables keep real FKs in
  their create migrations, and referential integrity on the `leads` columns is
  enforced in the Action layer.
