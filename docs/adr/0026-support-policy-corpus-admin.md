# ADR 0026 — Support policy corpus admin (P3.5d-c)

- **Status:** Accepted
- **Date:** 2026-07-17
- **PRD:** §6.13 (AI first-response / deflection layer — the corpus it answers from)
- **Supersedes / relates to:** ADR 0024 (deflection — deferred this), 0025 (triage/reply drafts — reply drafts read the same corpus), 0017 (tutor RAG — shares `knowledge_documents`)

## Context

ADR 0024 shipped deflection against a **seeder-only** corpus and named the consequence:
the corpus could only change by deploy, so deflection quality was pinned to the release
cycle. That is not a small gap. Deflection can only answer from documents that exist, and
the operational questions that drive most ticket volume (batch transfers, reschedule
rules, refund mechanics) were absent — so the feature could pass every test and deflect
almost nothing, indistinguishably.

This closes the code half of that gap. **It does not close the content half**, which is
not ours to close: writing a policy the company has not agreed to would put a promise in
a student's hands that nobody made.

## Decision

1. **Admin CRUD over `knowledge_documents` where `source_type='support'`**, gated
   `can:handle-tickets` — support policy belongs to the people answering the tickets, not
   to curriculum. No new table: ADR 0024 already established that a policy article *is* a
   knowledge document.

2. **Scoped to `source_type='support'` on every read and write.** The tutor's documents
   (course, program, lab, transcript) share the table but are machine-generated by
   `tutor:reindex`; editing one here would be silently reverted on the next rebuild. The
   controller 404s them rather than offering an edit that will not stick.

3. **Save and re-chunk are one action** (`SaveSupportDocument`). A document whose body
   changed but whose chunks did not is worse than no document: retrieval would serve the
   old policy while the admin screen showed the new one, and nobody could tell which the
   student was told. `IngestKnowledgeDocument` replaces chunks, so it is safe every save.

4. **`category` is required**, unlike the tutor's documents. Retrieval always scopes to
   the ticket's category, so an uncategorised policy is written but permanently
   unreachable. Rejecting it at the boundary beats a document that silently never matches.

5. **Audited** (`support_document.created|updated|deleted`). This is the text that tells
   students about their money; who changed it and when is not optional. `chunks_count` is
   exposed for the same reason — zero chunks means unreachable, which a policy author
   would otherwise never see.

6. **Deactivate is not delete.** `is_active=false` drops the document out of retrieval
   (the retriever already filters on it) while the text survives for the author to finish.
   Delete removes chunks with the document, so retrieval can never cite a policy that no
   longer exists.

## Consequences

- **Positive:** Policy can be corrected in minutes by the person who knows the answer,
  and the change reaches the next student immediately. The empty state says plainly that
  nothing is deflected until something is written.
- **Trade-offs:** No approval flow on policy text. Unlike a syllabus or a grade, this is
  staff writing their own words for staff-owned policy — the same reasoning that left
  reply drafts ungated in ADR 0025. If policy authorship later needs review, it wants the
  `Approve*` pattern, not a bespoke one. There is also no draft state beyond
  `is_active=false`, and no version history — the audit log records that a change
  happened and by whom, not the previous text.
- **The content gap is unchanged and is the whole ballgame.** Eight seeded documents,
  every fact transcribed from the PRD. Batch transfers, reschedule rules, recording-access
  windows, refund mechanics past the 30-day window, and missed-EMI handling are still
  unanswered because the PRD does not answer them. Tracked as founder input 6 in
  `docs/session-prompts.md`.
- **Deferred:** approval/versioning for policy text; bulk import; surfacing the
  deflection accept rate per document on this screen (the data exists in
  `ticket_deflections` and would tell an author which policy is not landing).

## Verification

`php artisan test` — full suite **508 passing** (up from 498), incl.
`Feature/Support/SupportDocumentAdminTest` (10): create chunks and audits the author;
**every edit re-chunks so retrieval never serves the old policy**; a policy written here
**changes what deflection actually tells a student** (end-to-end through the student
endpoint, asserting the new text reaches the prompt and the citation); deactivate removes
it from retrieval without destroying the text; delete removes chunks with it; the list
shows only support documents; editing or deleting a machine-generated tutor document
404s; a missing category is rejected; permission denial; and **cross-tenant denial** on
list and update. Pint clean. `npm run typecheck`, `lint`, `build` pass.

**Known gap (carried, unchanged):** `e2e/admin-support-triage.spec.ts` still has never
run green — the local box has a second Next process holding :3000 and sharing `.next`,
and the pre-existing `admin-support-desk.spec.ts` fails identically in that state. No
Playwright spec is added here for the same reason.
