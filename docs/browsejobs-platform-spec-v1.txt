1. What BrowseJobs is
BrowseJobs is an AI-driven IT skilling & placement platform. Founded in London (2013), expanded to India
(2020), office in Whitefield, Bengaluru. The core differentiator:
The syllabus is not written — it's reverse-engineered. An AI system monitors up to ~50 real & mock
interviews per day, extracts the questions companies are actually asking this month, and the course
syllabus is rebuilt around that live demand. Students study only what's actually asked.
The business model is trust-first: three free steps (counselling + written career report → live masterclass → 7-
hour Python bootcamp) before a student pays anything. Then a registration fee, and a placement fee that is 
only due after the student is actually placed.

5. Recommended Tech Stack (my CTO recommendation)
You asked me to choose. For a platform that is both a fast SEO marketing site and a rich authenticated LMS
with four roles, real-time-ish progress, video, and a payments + placement pipeline:
5.1 Stack
Framework:Next.js 15 (App Router) + TypeScript. One codebase serves SSR/SSG marketing pages
(great SEO, fast) AND the authenticated LMS (React Server Components + client interactivity). This
avoids running two separate apps.
Styling:Tailwind CSS with the design tokens from Section 2 wired into tailwind.config. Add a
small set of primitives (Button, Card, Kicker, StatBand, ProofPanel, PromiseCards) in a /components/
brand folder so the design system is enforced in code.
UI primitives: shadcn/ui (Radix under the hood) for accessible dialogs, dropdowns, tabs, toasts.
Restyle them with brand tokens.
Database:PostgreSQL. Relational integrity matters here (enrolments, payments, placement pipeline,
attendance).
ORM:Prisma. Type-safe, migrations, great DX with Claude Code.
Auth:Auth.js (NextAuth v5) with email/password + OTP, role-based sessions (Section 7). Or Lucia if
you prefer fewer abstractions. Passwords hashed with bcrypt/argon2.
File/video storage: S3-compatible (AWS S3 or Cloudflare R2). Video streamed via a provider (Mux or
Cloudflare Stream) — do NOT serve raw MP4s from the origin; use signed playback URLs so course
videos aren't freely downloadable.
Background jobs: a queue (BullMQ + Redis, or a hosted equivalent) for emails, WhatsApp sends,
CRM sync, certificate generation, reminder notifications.
Payments:Razorpay (India-first, UPI/cards/EMI). Orders + webhooks (Section 9).
Email: transactional provider (Resend / AWS SES). WhatsApp: Cloud API (primary channel for this
audience).
Search (optional later): Postgres full-text first; add Meilisearch/Typesense if catalogue grows.
Hosting: Vercel for the Next.js app (or a Node host if you prefer), managed Postgres (Neon/
Supabase/RDS), Redis (Upstash), R2/S3 for assets.
5.2 Why not keep PHP?
The current marketing site is PHP 8 + MySQL and is fine as a brochure site. But an LMS with four roles, video,
real-time progress, a placement CRM, and background jobs is a product, not a page. Next.js + Postgres gives
you: one language (TypeScript) across front and back, type-safe DB access, server components for speed +
SEO, and a huge ecosystem for auth/video/payments. It's the lower-risk long-term choice. Migration note:
port the existing marketing copy, courses, testimonials, FAQs, and settings from the current MySQL schema
into the new Postgres schema (Section 8) — the content is reusable; only the platform changes.

7. Auth & RBAC
Roles:student, instructor, placement, admin. A user has exactly one primary role (admin can
act across all). Store as an enum; gate every route + API by role.
Auth methods: email + password (argon2/bcrypt) and phone OTP (this audience is phone-first).
Optional Google sign-in.
Sessions: secure, httpOnly cookies; short-lived access + refresh, or Auth.js session. CSRF
protection on all mutations.
Route protection: middleware guards /(lms)/* by authentication; per-segment guards by role (/
admin/* → admin only, etc.). Never rely on hiding UI — enforce on the server/API for every action.
Account creation: a student account is auto-provisioned on successful paid enrolment (or admin
invite). Credentials sent via email + WhatsApp. Force password set on first login.
Permissions matrix (enforce server-side):
Student: own data only.
Instructor: assigned batches only.
Placement: candidate pipeline + job/placement data; read student progress; no billing edits.
Admin: all.
Security: rate-limit auth + lead + payment endpoints; audit sensitive actions; secrets in env vars only
(never in the repo); validate + sanitise all input (zod schemas on every API route).
